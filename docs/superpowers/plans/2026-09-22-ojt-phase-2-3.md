# OJT Phase 2–3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add minimal role-based authentication, authoritative work-hour progress, task monitoring, and requirement monitoring to the Phase 0 Vue/Laravel foundation.

**Architecture:** Use Laravel Sanctum first-party SPA/session authentication with Laravel middleware, policies, scoped queries, Form Requests, Eloquent models, and dedicated workflow actions. Vue uses the existing Axios client, a small Pinia auth store, Vue Router guards, and focused student/coordinator views; the backend is the only source of truth for ownership, status transitions, rendered minutes, and progress.

**Tech Stack:** PHP 8.2+, Laravel 12, Sanctum 4, MySQL/MariaDB for development, SQLite in-memory for PHPUnit, Vue 3, JavaScript, Vite, Vue Router, Pinia, Axios, Tailwind CSS, Vitest, Vue Test Utils, and Playwright.

**Spec:** `docs/superpowers/specs/2026-09-22-ojt-phase-2-3-design.md`

## Global Constraints

> ARCHIVED / HISTORICAL: Execute only when explicitly revisiting the earlier
> Phase 2–3 history; it does not override the current student-only product.

- Keep separate `frontend/` and `backend/` applications; do not introduce React, TypeScript, Inertia, or a Blade application UI.
- Use Sanctum first-party SPA/session authentication; never store long-lived access tokens in browser storage.
- Laravel is authoritative for authentication, authorization, validation, workflow transitions, rendered minutes, and progress calculations.
- Use dedicated action endpoints for workflow transitions; do not add a generic status PATCH endpoint.
- Students can access only their own internship records; coordinators can access only internships assigned to them.
- Official progress sums approved `work_logs.rendered_minutes` only; the frontend must not recalculate it.
- Work-log duration is calculated from `time_in`, `time_out`, and `break_minutes`; client-supplied rendered minutes are ignored.
- Work-log states are `draft`, `submitted`, `approved`, and `rejected`; task states are `to_do`, `in_progress`, `submitted`, `needs_revision`, and `completed`; requirement states are `not_submitted`, `submitted`, `approved`, and `rejected`.
- Use the existing Axios, Pinia, Vue Router, Tailwind, Laravel, and PHPUnit/Vitest foundations before adding files or dependencies.
- Use visible labels, keyboard-accessible controls, readable status text, responsive layouts, and loading/empty/success/validation/error/forbidden states.
- Do not modify real `.env` credentials, run destructive database resets, commit, or push unless the user explicitly requests it.
- Do not implement Phase 4 assistant logic, completion readiness, notifications, analytics/reports, certificates, uploads, GPS/QR/biometrics, payroll, chat, AI, or a complex admin portal.

## Review Focus

- A student or coordinator tampers with an unrelated record ID: the API returns a permission-safe 403/404 response and changes nothing; pin this in `AuthorizationTest.php`, `WorkLogTest.php`, `TaskTest.php`, and `RequirementTest.php`.
- A client spoofs `rendered_minutes` or submits impossible time/break values: the server calculates the authoritative value or returns 422; pin this in `WorkLogTest.php`.
- A caller repeats or bypasses a workflow transition: the API returns 409/422 and preserves the record; pin this in `WorkLogTest.php`, `TaskTest.php`, and `RequirementTest.php`.
- The split localhost frontend loses Sanctum session/CSRF state: login, refresh/current-user restoration, logout, and a protected request must work through the real browser; pin this in `AuthTest.php`, auth-store tests, and browser smoke.
- A failed or duplicate frontend submission must preserve entered values, show a human-readable error, and issue only one active request; pin this in the relevant Work Hours, Tasks, and Requirements view tests.
